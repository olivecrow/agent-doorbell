# Managed ffplay dependency

On Windows x64, npm's postinstall runs install.mjs. It downloads the pinned Gyan FFmpeg 8.1.1 essentials ZIP (109,282,242 bytes), checks its SHA-256, and extracts only ffplay.exe, LICENSE, and README.txt. It verifies each file's hash and stages the directory before installation. The installed player occupies about 103 MB. Downloads have a three-minute deadline, no automatic retry, and fail installation on error. Existing verified files are reused without network access. Runtime notifications never download anything.

The installer uses the MIT-licensed fflate dependency. ffplay itself is a separate GPL v3 executable from [Gyan's builds](https://www.gyan.dev/ffmpeg/builds/), a provider linked by [FFmpeg](https://ffmpeg.org/download.html). The downloaded LICENSE and README.txt retain its license, source revision, build configuration, and external-library versions. Doorbell's npm archive contains the installer and pinned manifest, not the binary; do not redistribute a binary-containing archive without satisfying the binary's applicable source and notice requirements. See [FFmpeg licensing](https://ffmpeg.org/legal.html).

The npm package contains no suitable modern ffplay binary dependency: ffplay-static 3.2.2 dates to 2017, and ffbinaries' current 6.1 catalog lists ffmpeg/ffprobe but no ffplay. The small installer therefore manages the external player dependency explicitly rather than introducing an outdated player or a second process wrapper.

If lifecycle scripts were disabled, run `npm run setup:player` in the installed agent-doorbell package directory. Normal npm installation runs it automatically. Unsupported OS/architecture combinations retain the existing absolute-PATH installation route and are not claimed as verified. An invalid existing managed installation fails closed; reinstall the package rather than silently overwriting it. The managed directory is package-local, so npm uninstall removes it without touching user settings or credentials.
